推送滞后排序

同时打开所有端点的订阅流，取服务端 createdAt 与本地接收时间的差值中位数。 这是真实的数据到达延迟，比 GetVersion 往返更接近你实际的使用体感。

🔍

严苛的可用性门槛

RPC 必须 getHealth + getLatestBlockhash + getMultipleAccounts 三项全过；很多看着通的端点其实只给 getSlot。 gRPC 必须 HTTP/2、返回版本、且真的能收到流数据。

🛡️

剔除需要 token 的

需要认证的 gRPC 端点全部丢弃并只保留计数——你拿到的每一行都是能直接连的， 不会写到一半才发现要 token。

⚡

Cloudflare 边缘访问

扫描与服务解耦。数据由扫描机推送，你从离自己最近的 Cloudflare 节点读取， 扫描机本身不承载任何成员请求。

📊

内核级 RTT

连接延迟取自内核 TCP_INFO 的 tcpi_rtt，不受进程被调度延迟影响—— 在已经跑满的机器上，用户态计时会严重失真。

🔁

失败自愈

扫描线程对任何异常都兜底，不会因为一次偶发超时就永久停摆。 连续失败次数与最后成功时间直接暴露在 /health。
